# Promotion Rules

## Promote To `docs/`

Use this when the draft becomes user-facing guidance:

- Installation or setup steps
- Configuration reference
- Deployment guidance
- Troubleshooting
- Provider setup instructions

## Promote To `docs/dev/`

Use this when the draft becomes maintainer knowledge:

- Architecture decisions
- Plugin development guidance
- Release or CI process
- Internal extension patterns

## Delete Or Shrink

Delete the draft when:

- The implementation is complete and durable docs were updated.
- The idea was rejected.
- The draft is stale and no longer actionable.

Shrink the draft when:

- Only a short decision record remains useful.
- The full TODO list has already been completed.

## Update Links

- Do not link spec drafts from user-facing `docs/README.md`.
- Developer-facing references may mention `docs/spec/README.md`.
- Search old file names after moving or deleting drafts.
