# X OIDC UI 质量

先阅读[UI 设计与组件约定](../../../docs/dev/UI_DESIGN.md)，再按页面范围定位实现。
该文档是技术选型与验证命令的维护来源；组件版本与运行行为以当前源码和依赖配置为准。

## 页面边界

- 管理台登录页使用本地 shadcn-vue 组件；其他管理页面仍使用 PrimeVue，用户门户仍使用
  原有 Vue 样式。优先沿用所在页面的体系，不把局部调整扩展成未授权的全站迁移。
- 统一认证页由服务端输出 HTML / CSS，采用同款视觉样式，不能直接运行 Vue 组件。
  保留 `script-src 'none'`；不要通过内联脚本或放宽 CSP 实现装饰性功能。
- shadcn-vue 源码位于 `apps/admin-web/src/components/ui/`。主题限定在 `.shadcn-theme`，
  不引入全局 preflight 影响旧页面；复用组件时核对样式和属性透传。

## 实施与验收

- 保留表单提交、OAuth state、URL 转义和返回地址校验；若修改这些认证行为，同时使用
  `$x-oidc-auth-provider`。
- 单一按钮的倒计时使用原生定时跳转与 CSS，保留取消入口和错误返回时的手动操作；
  相关条件见设计文档，不通过增加脚本绕过 CSP。
- 图标优先使用内联 SVG 或同源静态资源，检查真实加载结果和缓存，而非只看占位元素。
- 核对受影响页面的桌面与手机布局、键盘焦点、错误反馈及实际跳转。仅使用测试配置与虚构账号。
- 按设计文档选择相关测试、类型检查和构建；测试行为与回归问题，避免为视觉常量逐项写断言。
- 前端变更后核对已跟踪的装配产物与源码一致，不手改生成文件。
  文档变更使用 `$x-oidc-docs-quality`；提交与推送遵循 `AGENTS.md` 和工程质量工作流。
