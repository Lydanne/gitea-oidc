# 管理员初始化、OTP 与 Passkey

本文适用于本地密码账号。管理台和用户门户的“账号安全”入口均只管理当前账号；飞书等外部
身份提供者的安全设置仍在对应平台管理。

## 首次初始化管理员

启用 `admin.enabled` 和 `auth.providers.local.enabled` 后，空白部署首次启动会自动创建
`local.config.adminUsers` 中的第一个账号；未配置名单时使用 `admin`，并赋予
`admin.allowedGroups` 中的第一个组（默认 `x-oidc-admins`）。服务为该账号生成随机复杂临时密码，
不在日志中输出密码。

默认将临时用户名和密码写入 `passwordFile` 后追加 `.bootstrap.json` 的文件，例如
`.htpasswd.bootstrap.json`，文件权限为 `0600`。仅在部署机器上以服务账号查看文件并通过
可信渠道交给管理员。目录必须已存在且允许服务账号写入。

管理员使用临时密码登录后，会被要求再次输入临时密码和新密码。新密码至少 12 位、最多
72 字节，且包含大小写字母、数字和特殊字符；配置的 `passwordPolicy.minLength` 更大时
按更大值执行。修改完成前不会签发登录结果，也不能访问管理或门户 API。完成后临时密码立即
失效，临时凭据文件会删除。随后使用新密码重新登录，不会继续沿用临时密码验证得到的登录结果。

初始化配置位于 `auth.providers.local.config`：

```json
{
  "passwordFile": "/app/secrets/.htpasswd",
  "passwordFormat": "bcrypt",
  "adminUsers": ["admin"],
  "bootstrapAdmin": {
    "enabled": true,
    "credentialsFile": "/app/secrets/admin.bootstrap.json"
  }
}
```

`bootstrapAdmin.enabled` 默认启用，但仅在管理台和本地认证同时启用时执行自动初始化。
省略 `credentialsFile` 时使用上述默认路径。若继续完全手动管理初始管理员，可将
`bootstrapAdmin.enabled` 设置为 `false`，并提前准备有效的 htpasswd 文件。

已有 htpasswd 管理员或仓储中已有用户的部署保持原凭据，不会再自动创建管理员。初始化中断时
会复用已保存的初始化记录和临时密码安全重试。首次初始化记录一经保存，
重启不会重新生成；删除管理员账号也不会自动再创建一个新的管理员。

## 密码存储与持久化

通过页面设置的密码采用 bcrypt 保存至独立的 `account_security` 表，并优先于该账号原有
htpasswd 条目。不要继续通过修改旧 htpasswd 条目来重置已经由页面管理的密码。

安全表复用 `auth.userRepository` 的后端：SQLite 和 PostgreSQL 会持久化密码、OTP 和
Passkey；memory 仅用于开发，重启会丢失这些数据并重新初始化。安全记录绑定用户的随机记录
ID，删除并重建同名用户不会继承旧凭据。

密码哈希、OTP 密钥、恢复码哈希和 Passkey 公钥独立保存，不出现在用户详情或 OIDC Claims。
持久化安全表使用由 `oidc.cookieKeys` 派生的密钥进行 AES-256-GCM 加密；备份数据库时也必须
保留对应 Cookie Key。不要在没有保留旧 Key 的情况下直接替换已有 Key，参见
[生产运维手册](./OPERATIONS.md#cookie-keys)。

## 改密后的退出与重新登录

首次重设临时密码和后续修改密码都会撤销当前账号的管理台、门户 BFF 会话及 IdP 保存的
OIDC Session、Grant、授权码和用户令牌。其他账号已有的管理台和门户会话不受影响。
登录代际采用全局轮换，因此其他账号尚未完成的登录流程也可能需要重新发起。

改密前生成的 OAuth state、Passkey 登录流程、已验证的登录结果以及迟到写入的旧结果都不能
继续完成认证。系统先阻止该账号写入新的 OIDC 授权记录、轮换会话与登录代际，并完成旧记录
撤销，然后才保存新密码；撤销失败时不会保存新密码。并发的账号停用操作仍保持有效。
若新密码保存后的临时封锁清理失败，接口会报错，但已保存的新密码不会回退；需排除存储错误
后重新登录。

改密后，安全设置页会转入新的登录流程；首次强制改密页会提示重新登录。使用新密码完成认证
后才能继续。第三方应用自己保存的业务会话仍由该应用的退出策略管理；已交付且仅离线验签的
令牌，其有效期和撤销检查仍取决于消费方策略。

## 绑定与使用 OTP

1. 登录管理台或门户，进入“账号安全”。
2. 输入当前密码，点击“绑定认证器”。
3. 在支持 TOTP 的认证器中手动添加显示的密钥：SHA-1、6 位、30 秒。
4. 在 5 分钟内输入认证器生成的动态码，确认后才会启用 OTP。
5. 将仅显示一次的 10 个恢复码保存在密码管理器中，再隐藏页面上的恢复码。

启用后，本地密码登录需同时填写动态码或一个未使用的恢复码。动态码允许前后一个时间窗口
的时钟误差，但同一个时间步的码只能消费一次；刚绑定或刚完成其他验证时，请等待下一枚
动态码。恢复码每个只能使用一次，并可用于丢失认证器时登录或停用 OTP。

停用 OTP 需要当前密码和有效动态码或恢复码，停用后旧密钥与剩余恢复码全部作废。
如需重新生成恢复码，应停用后重新绑定。不要把密钥或恢复码复制到聊天、日志或工单。

## 绑定与使用 Passkey

1. 使用 HTTPS 访问服务；本机开发可使用 `localhost` 或 loopback 安全上下文。
2. 在“账号安全”输入当前密码，已启用 OTP 时还需一枚有效动态码或恢复码。
3. 填写设备名称，点击“添加 Passkey”，按浏览器提示使用指纹、面容、设备 PIN 或安全密钥。
4. 后续登录时，选择“使用 Passkey 登录”，输入用户名后完成设备验证。

每个账号最多绑定 10 个 Passkey。Passkey 必须完成用户验证，可替代密码和 OTP 登录。
绑定和登录都校验站点 Origin、RP ID、一次性挑战及浏览器绑定；挑战有效期为 5 分钟。
登录只会接受当前有效账号上已绑定的公钥。

RP ID 来自 `server.url` 的主机名。迁移到不同主机名后，需要重新绑定 Passkey。
移除 Passkey 同样需要当前密码和已启用的 OTP；移除后该凭据不能再次登录。

## 常见问题

- **临时文件无法写入**：确认目标目录存在，服务账号有写权限；不要开放目录给其他用户。
- **提示必须改密**：使用临时密码完成重设，不能通过直接请求后台 API 绕过。
- **验证码失败**：检查设备时间、是否已使用当前动态码，或改用未使用的恢复码。
- **Passkey 不可用**：检查 HTTPS、浏览器支持、`server.url` 与实际访问的 Origin 是否一致。
- **挑战已过期或验证失败**：重新开始绑定或登录，不要重复提交旧挑战。
- **密码已更新但旧 htpasswd 仍存在**：页面设置的密码优先；旧条目不能恢复旧密码。
- **丢失认证器和全部恢复码**：如已绑定 Passkey，可先使用 Passkey 登录；修改安全设置仍需
  当前密码和 OTP 验证，请联系部署维护者执行经授权的离线恢复，不提供免验证的远程重置接口。
